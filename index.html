Problem-Solving

Troubleshooting cases from my Arduino projects and computer use. Click a case to read it.

Problem: While building our Gas Leakage Alarm System, we got an error every time we tried to upload the code to the Arduino Uno.

Possible Causes: Wrong board or COM port selected in the Arduino IDE, a bad USB cable, a mistake in the code, or a defective Arduino board.

Diagnostic Procedure: We checked that the correct board (Arduino Uno) and COM port were selected, tried the USB cable again, and tested with a simple example code. The upload still failed, even with code that should work, so the problem was not in our code or settings.

Solution: We found that the Arduino Uno itself was defective. We replaced it with a new Arduino Uno, uploaded the code successfully, and rebuilt the alarm. It worked perfectly.

Lesson Learned: Troubleshoot one thing at a time: settings, cable, code, then hardware. Testing with a simple example helps prove if the problem is the code or the board.

Related project: Gas Leakage Alarm System (school team project, view code)

Problem: When I first opened my Sales Analysis project, the summary cards were empty and the bar chart did not appear.

Possible Causes: Wrong file path to script.js, an error in the JavaScript code, the sales data list was empty or in the wrong format, or the browser was showing an old version of the page.

Diagnostic Procedure: I checked that script.js and style.css loaded, and looked for error messages in the browser. There were none, so I checked the data list in the page and found that it was empty. I compared it with sales.csv, which has 15 rows.

Solution: I put the 15 rows from sales.csv into the data list and reloaded the page. The totals and the chart appeared. I confirmed the result by adding the numbers myself: the total sales of PHP 21,425 matched.

Lesson Learned: When a page is blank, check the data before blaming the code. Compare the result with a manual calculation.

Related project: Sales Analysis

Problem: A tracker can break if the user leaves a field empty or types a zero amount. It would add blank entries and give a wrong balance.

Possible Causes: No checking of the input before adding it, a text typed in the amount box, or an amount of zero or less.

Diagnostic Procedure: I tested the form with wrong input: an empty description, an amount of 0, and an expense bigger than the income. I watched the balance each time.

Solution: I added input checking in script.js. The form now shows a message if the description is empty or the amount is not greater than 0. The balance turns red when it is negative. After the fix, I tested again: PHP 1,000.00 income minus PHP 150.50 and PHP 50.00 expenses gave PHP 799.50.

Lesson Learned: Test with wrong input, not only correct input. Always check what the user types before using it.

Related project: Allowance Tracker

Problem: The computer became very slow. Programs took a long time to open and sometimes froze.

Possible Causes: Too many programs running, a program using too much memory or CPU, too many startup apps, or a full hard drive.

Diagnostic Procedure: I pressed Ctrl + Shift + Esc to open Task Manager. I sorted the list by CPU and Memory to see which programs were using the most resources. I also checked the Startup tab and the free space on the drive.

Solution: I closed the programs I was not using, ended a program that was using too much memory, and disabled unnecessary startup apps. I also deleted temporary files to free up space. The computer became faster.

Lesson Learned: Task Manager helps find the real cause before restarting or reinstalling. Only end programs that I know are safe to close.

Problem: While building this portfolio, my certificate pictures did not appear on the page. Only broken image icons showed.

Cybersecurity Case Study: SQL Injection

A beginner-level look at a common website weakness and how to prevent it.

Related project: IT Basics Quiz (it has a question about strong passwords).

1. What is the vulnerability?

SQL injection is a weakness in websites that use a database. It happens when the website puts whatever the user types directly into a database command (SQL query). An attacker can type special text that changes the command and makes the database do something it should not do.

2. How can it happen?

For example, a login form takes the username and password and builds a query by joining text together. If someone types ' OR '1'='1 in the password box, the query becomes always true, and they may log in without the correct password.

Unsafe (do not use):

$sql = "SELECT * FROM users
  WHERE username = '" . $_POST['user'] . "'
  AND password = '" . $_POST['pass'] . "'";

3. What are the risks?

  • Logging in as another user without a password
  • Stealing private data like names, emails, and passwords
  • Changing or deleting records in the database
  • Breaking the Data Privacy Act of 2012 if personal data leaks

4. How can developers prevent it?

Use prepared statements. The query is written first with a placeholder (?), and the user's input is sent separately as plain data, so it cannot change the command.

Safe:

$stmt = $conn->prepare(
  "SELECT * FROM users WHERE username = ?");
$stmt->bind_param("s", $_POST['user']);
$stmt->execute();

5. What security practices should be implemented?

  • Use prepared statements for every query with user input
  • Check user input (type, length, allowed characters)
  • Save passwords as hashes, never as plain text
  • Show simple error messages to users, not database errors
  • Give the database account only the permissions it needs
  • Test only on my own system, never on other people's websites

Reflection

Before I took BSIT, I only knew technology as a user. I used apps, social media, and Microsoft Office, but I never thought about how programs were made or how a computer could control things like lights and sensors. Studying at Datamex College of Saint Adeline changed that. I started to see technology as something I can build and fix, not only something I use.

The most important thing I learned is to solve problems step by step. When something does not work, I now read the error message, test one small part at a time, and look for the real cause instead of guessing. This habit helped me in almost every project, from my Arduino circuits to this portfolio website.

My Arduino projects taught me the most. I learned how to connect LEDs, a gas sensor, an LCD, and a buzzer, and how to control them with code. Seeing a circuit react to the code I wrote was the moment I really enjoyed programming. On my own, I built three practice projects: an IT Basics Quiz, a Sales Analysis with Excel and SQL, and an Allowance Tracker. With my team at school, I also worked on Eskinita Apparel, an online ordering and inventory system, and OnlyJobs, a job finder website. These projects showed me how a web page, a database, and a user's needs fit together, and that teamwork and clear communication are as important as the code itself.

My biggest challenge was finding the cause of a problem when nothing worked. In our Gas Leakage Alarm project, the code would not upload, and after a long time of checking we found that the Arduino Uno itself was defective. While building this portfolio, my images would not show because my files were in the wrong folders. These problems were frustrating, but they taught me to be patient and to check the simple things first before blaming the code.

Outside the classroom, I joined webinars on Arduino, web development, Linux, network security, and digital office skills. They gave me a small look at areas of IT that I have not studied deeply yet, and they showed me how many paths I can take in this field. I also learned that AI tools can be helpful, but I must still understand, test, and check my own work. I cannot just copy an answer without knowing why it works.

I know that I am still a beginner. I still need to improve my MySQL, strengthen my HTML and CSS design, learn JavaScript and PHP, and learn to use GitHub better. I also want to explain my work more clearly, because a good project is not useful if I cannot present it well. To improve, I plan to keep building small projects, practice a little every week, and ask for feedback from my teachers and classmates.

My goal is to become a reliable and honest IT professional who keeps learning and builds websites and systems that help people. I want to start as a Junior Web Developer or IT Trainee, where I can learn from experienced developers and grow step by step.

I went from only using applications to building simple circuits, databases, and web pages. I am ready to start my career in IT. I may not know everything yet, but I have hands-on projects, I can troubleshoot step by step, and I am willing to work hard and keep growing.
